# Sonic Animation Viewer PRD

## 1. 제품 개요

Sonic 스프라이트 시트의 동작 애니메이션을 순서대로 재생해 확인하는 학습용 데스크톱 프로그램이다. 플레이 가능한 게임이 아니라, 스프라이트 시트의 프레임과 반복 동작을 보여주는 뷰어를 제공한다.

## 2. 목표 및 범위

### 목표

- 시트에 포함된 모든 실제 동작을 프레임 순서에 맞게 재생한다.
- 동작별 5회 반복, 동작 간 1초 대기, 전체 무한 순환을 구현한다.
- 캐릭터를 확대해 동작을 알아보기 쉽게 표시한다.
- 작고 실행 가능한 단계로 개발하고 각 단계의 결과를 확인한다.

### 제외 범위

- 플레이어 입력에 따른 이동, 충돌, 점수 등 게임 기능
- 애니메이션 선택 메뉴, 마우스 조작, 재생 속도 조절 UI
- 스프라이트 시트 편집기나 별도의 애니메이션 메타데이터 파일

## 3. 실행 환경 및 산출물

| 항목 | 기준 |
| --- | --- |
| 언어 및 라이브러리 | Python, `pico2d` |
| 실행 파일 | `Labs/LEC09/sonic_animation_viewer.py` |
| 이미지 리소스 | `Labs/LEC09/sonic-sprite.png` |
| 캔버스 크기 | 1200×800 픽셀 |
| 소스 구성 | 실행 코드는 단일 Python 파일로 작성. 이미지 파일은 외부 리소스로 유지 |

이미지 경로는 현재 작업 디렉터리가 아니라 실행 파일의 위치를 기준으로 결정한다. 이미지가 없거나 로드에 실패하면 대상 경로를 알 수 있는 오류를 표시하고 종료한다.

## 4. 스프라이트 시트 해석

`sonic-sprite.png`에는 실행에 사용할 프레임 메타데이터가 별도로 제공되지 않는다. 구현 전에 이미지를 확인해 각 동작의 프레임 범위와 순서를 정하고, 그 정보를 실행 파일 안에 명시한다.

- 프레임 영역은 원본 이미지의 픽셀 좌표로 정의한다.
- 시트의 배치는 위에서 아래, 동작 안에서는 왼쪽에서 오른쪽 순서를 기본으로 해석한다. 실제 동작 흐름이 다르면 올바른 순서를 코드에 명시한다.
- 제목, 크레딧, 장식 등 캐릭터의 동작 프레임이 아닌 요소는 재생 대상에서 제외한다.
- 동작별 프레임 정의와 재생 순서는 코드의 한 곳에서 확인하고 수정할 수 있게 구성한다.
- 시트의 모든 동작을 포함하고, 동작 간 프레임 혼합이나 프레임 누락이 없도록 한다.

## 5. 기능 요구사항

### 애니메이션 재생

| ID | 요구사항 |
| --- | --- |
| FR-01 | 시트에서 확인한 모든 동작을 정해진 순서대로 재생한다. |
| FR-02 | 각 동작은 정의된 첫 프레임부터 마지막 프레임까지 순서대로 재생한다. |
| FR-03 | 다음 동작으로 넘어가기 전에 현재 동작의 전체 프레임 시퀀스를 정확히 5회 재생한다. |
| FR-04 | 5회 재생을 마친 뒤 1초 대기하고 다음 동작을 시작한다. 마지막 동작 뒤에도 1초 대기한다. |
| FR-05 | 마지막 동작 다음에는 첫 동작으로 돌아가 전체 재생 과정을 무한 반복한다. |
| FR-06 | 프레임 간격은 코드에서 조정할 수 있도록 상수로 둔다. 초기 기준은 프레임당 약 0.08초로 한다. |

### 화면 표시 및 입력

| ID | 요구사항 |
| --- | --- |
| UI-01 | 캔버스 크기는 1200×800 픽셀로 한다. |
| UI-02 | 캐릭터의 표시 높이는 캔버스 높이의 약 절반, 즉 약 400픽셀을 기준으로 확대한다. |
| UI-03 | 확대 후에도 원본 가로세로 비율을 유지하고 화면 밖으로 잘리지 않게 한다. |
| UI-04 | 캐릭터는 화면 중앙 부근에 표시한다. 프레임 간 불필요한 위치 흔들림은 줄이되 점프 등 동작에 필요한 위치 변화는 유지한다. |
| UI-05 | 프레임을 그린 뒤 캔버스를 갱신해 화면에 즉시 반영한다. |
| IN-01 | 창 닫기 이벤트와 `ESC` 키 입력으로 프로그램을 종료할 수 있다. |
| IN-02 | 애니메이션 재생 중뿐 아니라 1초 대기 중에도 종료 입력에 응답한다. |

## 6. 검수 기준

| ID | 확인 방법 | 통과 기준 |
| --- | --- | --- |
| AC-01 | 실행 | 지정 환경에서 실행하면 1200×800 캔버스가 열리고 오류 없이 시작한다. |
| AC-02 | 리소스 경로 | 다른 작업 디렉터리에서 실행해도 실행 파일 기준 위치의 `sonic-sprite.png`를 불러온다. |
| AC-03 | 시트 범위 | 실제 동작은 모두 재생되고 제목·크레딧·장식은 재생되지 않는다. |
| AC-04 | 프레임 순서 | 각 동작의 프레임이 누락되거나 뒤섞이지 않고 의도한 순서로 재생된다. |
| AC-05 | 반복 | 다음 동작으로 넘어가기 전에 현재 동작이 정확히 5회 재생된다. |
| AC-06 | 대기 및 순환 | 각 동작 뒤 약 1초 대기하며, 마지막 동작 뒤 첫 동작부터 다시 재생한다. |
| AC-07 | 크기 및 배치 | 캐릭터 높이가 약 400픽셀이고 비율이 유지되며 화면 경계 안에 표시된다. |
| AC-08 | 종료 | 재생 중과 대기 중 모두 창 닫기 또는 `ESC` 입력으로 종료할 수 있다. |
| AC-09 | 리소스 오류 | 이미지 로드 실패 시 대상 경로를 확인할 수 있는 오류를 표시하고 종료한다. |

## 7. 개발 절차 및 규칙

- 아래 순서대로 실행 가능한 기능을 단계적으로 추가한다. 각 단계를 직접 실행해 확인한 뒤 해당 변경을 커밋하고 다음 단계로 진행한다.
- 커밋 메시지는 표에 제안된 제목처럼 반드시 한글로 작성한다.
- 기본 계획은 21개 커밋이다. 검수 중 수정이 필요하면 관련 단계의 커밋을 추가해도 된다.

| 순서 | 커밋 메시지 | 변경 내용 및 확인 |
| --- | --- | --- |
| 01 | `뷰어 파일과 기본 창 구성` | 단일 실행 파일을 만들고 1200×800 캔버스를 연다. 창이 정상적으로 나타나는지 확인한다. |
| 02 | `화면과 재생 기준값 정의` | 캔버스 크기, 목표 표시 높이 400픽셀, 프레임 간격 0.08초, 반복 횟수 5회, 대기 시간 1초를 상수로 모은다. |
| 03 | `기본 종료 입력 처리` | 창 닫기와 `ESC` 입력을 받아 프로그램을 종료한다. |
| 04 | `이미지 경로를 실행 파일 기준으로 설정` | 현재 작업 디렉터리와 관계없이 실행 파일 옆의 스프라이트를 찾도록 경로를 구성한다. 다른 위치에서 실행해 확인한다. |
| 05 | `스프라이트 로드와 오류 안내 추가` | `sonic-sprite.png`를 불러오고, 파일이 없거나 열리지 않을 때 경로가 포함된 오류를 표시한다. |
| 06 | `스프라이트 시트 동작 영역 분석` | 이미지에서 실제 동작 그룹, 각 그룹의 프레임 경계와 순서를 확인해 구현 기준으로 기록한다. 비동작 요소를 구분한다. |
| 07 | `동작별 프레임 좌표 정의` | 확인한 프레임 좌표와 동작 재생 순서를 코드의 한 곳에 데이터로 정의한다. |
| 08 | `스프라이트 프레임 추출 함수 구현` | 원본 이미지의 좌표와 크기로 지정 프레임을 선택하는 코드를 만들고 한 프레임을 확인한다. |
| 09 | `프레임 좌표계 변환 처리` | 스프라이트 시트의 위쪽 기준 좌표를 `pico2d`의 이미지 좌표계에 맞게 변환한다. 경계 프레임이 올바르게 잘리는지 확인한다. |
| 10 | `캐릭터 한 프레임 화면에 출력` | 추출한 프레임 하나를 캔버스에 그려 이미지 방향과 잘림 여부를 확인한다. |
| 11 | `캐릭터 확대와 비율 유지 구현` | 캐릭터 높이를 약 400픽셀로 확대하고 원본 비율이 유지되는지 확인한다. |
| 12 | `프레임 기준 위치 보정` | 동작 프레임의 기준점을 맞춰 불필요한 위치 흔들림을 줄이고 화면 안에 표시한다. |
| 13 | `프레임 시간 간격 적용` | 설정한 간격에 맞춰 화면 프레임이 갱신되도록 시간 처리를 추가한다. |
| 14 | `첫 번째 동작 프레임 재생` | 첫 번째 동작의 프레임을 정의된 순서대로 한 차례 재생한다. |
| 15 | `동작 프레임 순환 처리` | 한 동작의 마지막 프레임 뒤에 첫 프레임부터 다시 재생되는지 확인한다. |
| 16 | `동작별 다섯 번 반복 구현` | 다음 동작으로 넘어가기 전에 전체 프레임 시퀀스가 정확히 다섯 번 재생되도록 한다. |
| 17 | `동작 사이 일 초 대기 추가` | 다섯 번째 재생이 끝난 뒤 다음 동작 전까지 1초 대기하도록 한다. |
| 18 | `나머지 동작 프레임 등록` | 분석한 모든 동작의 프레임 정의를 추가하고, 각 그룹을 개별 재생해 누락 여부를 확인한다. |
| 19 | `동작 간 순차 전환 구현` | 한 동작의 반복과 대기가 끝나면 등록된 순서의 다음 동작으로 전환한다. |
| 20 | `마지막 동작 뒤 전체 순환 구현` | 마지막 동작과 대기 후 첫 동작으로 돌아가 전체 재생이 반복되는지 확인한다. |
| 21 | `재생과 대기 중 종료 응답 보장` | 프레임 재생 중 및 1초 대기 중에도 창 닫기와 `ESC` 입력이 처리되는지 확인하고 전체 검수 기준을 실행한다. |

각 커밋은 한글 메시지를 사용하며, 커밋 후에도 실행 가능한 상태를 유지하는 것을 원칙으로 한다. 검수에서 발견한 프레임 좌표, 재생 순서, 크기 또는 입력 처리 문제는 수정 후 별도 한글 커밋으로 기록한다.
